# Правила работы с Markdown

Документация «Таскбука» хранится в репозитории в формате Markdown и собирается в сайт с помощью MkDocs. Большинство правил проверяет линтер markdownlint. Настройки линтера — в файле `.markdownlint.yaml`.

## Файлы и папки

- Один документ — один файл `.md`.
- Имя файла — латиницей, строчными буквами, через дефис: `create-project.md`.
- Файлы группируются в папки по разделам документации.
- Новый файл добавляется в навигацию в `mkdocs.yml`.

## Синтаксис

| Элемент | Как писать | Как не писать |
| --- | --- | --- |
| Заголовок | `## Заголовок` | `Заголовок` с подчёркиванием `---` |
| Маркированный список | `- пункт` | `* пункт`, `+ пункт` |
| Нумерованный список | `1.` в каждом пункте | Ручная нумерация `1.`, `2.`, `3.` |
| Полужирный | `**текст**` | `__текст__` |
| Курсив | `*текст*` | `_текст_` |
| Блок кода | Тройные обратные кавычки с языком | Отступ в 4 пробела |

Нумерация `1.` в каждом пункте позволяет добавлять и удалять шаги без перенумерации.

## Отступы и пустые строки

- Вложенный список сдвигается на 4 пробела. Этого требует MkDocs.
- Заголовки, списки, таблицы и блоки кода отделяются пустой строкой сверху и снизу.
- В конце файла — одна пустая строка.
- Не оставляйте пробелы в конце строк.

## HTML

HTML-теги в Markdown не используются. Если нужного элемента нет в Markdown, используйте расширения MkDocs: блоки-примечания, клавиши, сворачиваемые блоки.

## Длина строки

Ограничения длины строки нет. Пишите один абзац в одну строку: так проще читать изменения в pull request.
