# Руководство по стилю документации «Таскбук»

«Таскбук» — облачный сервис для управления задачами и проектами. У сервиса есть веб-приложение, мобильные приложения и публичный REST API.

Руководство описывает, как писать и оформлять документацию сервиса: справку для пользователей, руководства администратора, документацию API и описания изменений.

## Для кого руководство

- Технические писатели, которые готовят справку и документацию API.
- Разработчики, которые описывают методы API и пишут описания изменений.
- Менеджеры продукта и специалисты поддержки, которые дополняют справку и статьи базы знаний.
- Ревьюеры, которые проверяют документацию перед публикацией.

## Цели руководства

- Документация читается как один текст, даже если её пишут разные авторы.
- Читатель быстро находит ответ и сразу может выполнить действие.
- Автор не тратит время на решение одних и тех же вопросов: как писать термины, как оформлять списки, как обращаться к читателю.
- Ревью проходит быстрее: спорные места решаются ссылкой на правило.

## Читатели документации

| Читатель | Что ему нужно | Какие документы читает |
| --- | --- | --- |
| Пользователь | Выполнить задачу в интерфейсе | Инструкции, ответы на вопросы |
| Администратор пространства | Настроить доступы, интеграции, оплату | Руководство администратора |
| Разработчик интеграции | Вызвать метод API и обработать ответ | Справочник API, примеры кода |

## Как пользоваться руководством

1. Перед тем как писать новый документ, выберите шаблон в разделе [Шаблоны](doc-templates/how-to.md).
1. Пишите текст по правилам разделов [Стиль изложения](style/tone.md) и [Оформление текста](formatting/structure.md).
1. Проверьте термины по [словарю](glossary.md).
1. Запустите линтер и исправьте замечания. Как это сделать, описано в [CONTRIBUTING.md](https://github.com/F0x1d/style-guide-project/blob/main/CONTRIBUTING.md).

## Обязательность правил

В руководстве используются три уровня требований:

- **Обязательно** — правило соблюдается всегда. Нарушение блокирует публикацию.
- **Рекомендуется** — правило соблюдается, если нет веской причины его нарушить. Причину указывают в описании pull request.
- **Допустимо** — вариант разрешён, но не является предпочтительным.

Если правило не указывает уровень, оно обязательное.

## Что делать, если правила нет

1. Посмотрите, как этот случай решён в уже опубликованной документации «Таскбука».
1. Если там нет ответа, используйте [руководство по стилю Google для разработчиков](https://developers.google.com/style). По вопросам русского языка — «Справочник издателя и автора» А. Э. Мильчина и Л. К. Чельцовой и портал [Грамота.ру](https://gramota.ru/).
1. Предложите новое правило через pull request в этот репозиторий.
