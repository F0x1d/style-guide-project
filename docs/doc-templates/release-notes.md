# Шаблон: описание изменений

Описание изменений рассказывает пользователям, что нового появилось в версии. Читатель хочет быстро понять, что изменилось для него.

## Правила

- Пишите о пользе для читателя, а не о внутренней работе команды: «Теперь можно назначить на задачу несколько исполнителей», а не «Переписали модуль назначений».
- Изменения группируются по разделам: «Новое», «Улучшения», «Исправления».
- Каждое изменение — один пункт списка из одного-двух предложений.
- Если изменение требует действий от читателя, начните пункт со слова **Важно**.
- Дата выпуска пишется в формате ДД.ММ.ГГГГ.
- Не указывайте номера внутренних задач и имена разработчиков.

## Шаблон

```markdown
# Версия [номер] — [ДД.ММ.ГГГГ]

## Новое

- [Что теперь можно сделать.] [Где это найти.]

## Улучшения

- [Что стало удобнее или быстрее.]

## Исправления

- [Что исправлено, в прошедшем времени: «Исправлена ошибка, из-за которой…».]
```
